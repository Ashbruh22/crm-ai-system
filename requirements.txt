# Must fit a ~512 MB CPU container (spec section 0). Training-only packages
# (torch, optuna, mlflow, faker) live in requirements-train.txt and are never
# copied into the service image.
#
# Removed in phase 1, deliberately:
#   tensorflow==2.21.0  ~600 MB, alone over budget. The LSTM is served from
#                       artifacts/lstm.onnx via onnxruntime (~15 MB) instead.
#   optuna, mlflow      training/MLOps only.
#   scikit-learn pin    was pinned to a PRE-RELEASE (1.9.0) purely to match the
#                       ml/pipeline.joblib pickle. Feature engineering is now
#                       plain code in app/features/build.py with hard-coded
#                       vocabularies, so no pickled encoder and no pin.
#   psycopg2-binary     asyncpg is the driver in use; one is enough.

# NOTE: the `shap` package is deliberately NOT a runtime dependency.
# Explanations come from XGBoost's own TreeSHAP (booster.predict(
# pred_contribs=True)) -- the same algorithm, computed by the library that
# built the trees. shap's TreeExplainer re-parses the booster and, against
# xgboost 3.2, returned attributions that did not sum to the prediction
# (errors up to 0.38 in log-odds). Dropping it also removes numba and llvmlite
# (~70 MB) from the image. See app/models/registry.py:shap_contribs.
